# Physical Safari check — not performed in this Linux environment

Use a small iPhone, a notched/Dynamic Island iPhone, and an iPad. Record the model, OS version, build commit and delivery URL with any result.

1. Open the hosted homepage fresh and with an existing save. Expand/collapse Safari's toolbars, rotate, pinch zoom and use iPad Split View/Stage Manager. Check the safe areas, hero, Continue/New action, Explore five games shortcut and all five activity cards.
2. Edit both Fairy and Panther heroes, including the name with the real keyboard. Return home and reload. Verify the same appearance, equipment, learning profile, earned progress and sound preference remain.
3. Use every activity and return home. Check touch targets, the real Written Practice keyboard/submission flow, modal scrolling, and keyboard/VoiceOver focus. Enable Reduce Motion and repeat the primary navigation.
4. Switch apps and lock/unlock during home, a question and a Librarian storm. Return, close/reopen and confirm no stuck movement, duplicate sounds, extra grading or unexpected loss of saved progress. Temporary interrupted duels retain their existing restart behavior.
5. With the game already loaded, use Airplane Mode, navigate, answer and save. Reconnect and reload. Separately verify the intended standalone-HTML delivery workflow: Files/Quick Look is not assumed to execute HTML as a website. Home Screen bookmarking is not proof of offline PWA support.
6. Observe a detailed winged hero and each mode for a minute, then reopen them repeatedly. Note tap delays, frame stalls, heat, Safari reloads or memory-pressure effects. Desktop engine tests do not establish device FPS, retina GPU cost or battery life.

Actual iOS keyboard/toolbar behavior, VoiceOver, lock/unlock, physical-device performance and iOS standalone execution remain untested until recorded by a device tester.
